Short answers

Settings button next to the main button?
Yes, keep one visible Settings button.

A plain Settings button next to the main button is clean and professional. Options for how it looks: text only (today), text with your app’s small icon, a gear, or a sliders icon, small or large. My pick: small, with your app icon.

Do I need a gear icon?
No.

No. Your app’s own 16 px icon next to the word “Settings” reads as “ClickTo3D Settings”, and still shows an icon if someone adds it to the Quick Access Toolbar. A gear is fine too if you prefer it.

Windows look or add-on look?
Stay native, but modern.

A Revit tool should look like part of Revit, and Revit’s own windows look like Windows. Today’s ClickTo3D window looks dated rather than native: it uses the old WinForms default font and fixed pixel positions. The recommended “Native Modern” design keeps the Windows look with Windows 11 controls.

Height changes often, box size rarely
Height first, with − / + steps.

Inside the Settings window, height comes first with − / + steps and arrow-key steps; box size and view name move lower. One click on Settings, change the height, Enter.

Same theme for ClickTo3D and ClickToSection?
One shared template.

Today the two windows differ in font, unit buttons, button style and how errors appear. One template gives both apps, and every future app, the same header, rows, unit switch and footer.

Icon
Keep the shipped icon.

You preferred the shipped icon’s soft look over the sharper test versions, so it stays as it is. Optional extra: 48 and 64 px copies made the same way, for 150 % and 200 % screens.

Ribbon: how users reach Settings

Add-Ins tab · both apps · Revit light and dark theme

Both apps follow Autodesk’s ribbon guidance today: one panel each on the Add-Ins tab, with the main command as the large button on the left. Settings stays a visible, one-click button; the question is only how it looks. Use the switch to see each option in Revit’s light and dark themes.

Settings button: how it can look

If you keep a visible button: S2, a small “Settings” button with your app’s own icon, is my pick. If you prefer the slide-out (A, opened), that works too: it is Autodesk’s recommended spot, and Settings stays a normal command that ribbon tools and the Quick Access Toolbar can still pick up.

One clean button, always visible, one click. No gear, and it still makes sense on the Quick Access Toolbar. If you’d rather keep pure text, today’s button (or S1) is fine: it isn’t unprofessional. A gear (S3) is also perfectly professional if you prefer the universal sign. Thinnest: T1, an icon-only button with your app icon (about half today’s width); it needs one quick test in Revit because the API normally wants a label.

Direction 1 · Revit Classic

Plain

Looks like Revit’s own option dialogs: grey face, group boxes, OK and Cancel at the bottom right.

Good

  • Feels built-in; nothing to learn.
  • Spin buttons make height changes quick.
  • Simplest to build and maintain.

Less good

  • Looks older than Windows 11 and Revit 2025+ palettes.
  • Group boxes take space; ClickToSection needs two columns.
  • No room for helper text or diagrams.

Direction 2 · Native Modern

Recommended

Still plainly Windows (system font, standard title bar, Windows 11 controls and accent blue), but cleaner. Height comes first with step buttons. The same template serves every app.

Good

  • Fits Windows 11 and current Revit; reads as native, not as a skin.
  • The diagram explains Above / Below at a glance.
  • One template for all your apps; a dark palette is ready if Revit dialogs go dark.
  • ClickToSection’s rarely used marker options can fold away.

Less good

  • ClickTo3D’s window moves from WinForms to WPF (UI code only; the settings file and logic stay).
  • A little more styling code to share between apps.

Direction 3 · Branded Suite

Product look

A coloured header band, white cards and brand-blue pills: it reads as one software family.

Good

  • Strong family identity across apps.
  • The hub idea gives one place for every app’s settings later.

Less good

  • Looks like an add-on inside Revit, the opposite of what Revit users expect from small tools.
  • Brand styling dates faster than native styling.
  • A shared hub needs a shared component across separately sold apps.

Future-proof setup for all your apps

Revit 2024 (.NET Framework 4.8) to 2027 (.NET 10)
  1. WPF for every Settings window. It runs on .NET Framework 4.8 (Revit 2024) and .NET 8 / 10 (Revit 2025–2027), lays out cleanly at any Windows scaling, and ClickToSection already uses it. ClickTo3D’s WinForms window would move over; its settings file and checks stay the same.
  2. One shared style file with the colours, fonts and controls (number box with − / +, unit switch, footer buttons). Each app includes it, so every new app gets the same look without extra design work.
  3. Revit owns every window. Open each Settings window with Revit’s main window handle as owner (UIApplication.MainWindowHandle), centred on Revit.
  4. Follow Revit’s theme where Revit does. Since Revit 2024 the ribbon and palettes can be dark, and add-ins can read the theme (UIThemeManager.CurrentTheme) and react when it changes (ThemeChanged). Ribbon icons can switch per theme; dialogs stay light like most of Revit’s own, with a dark palette ready in the style file.
  5. Official ribbon API only (push buttons and the slide-out). Internal APIs such as the panel corner arrow can break with any Revit update.
  6. Same words and keys in every app: Feet / Meters, Reset to defaults, Save, Cancel. Enter saves, Esc cancels, ↑ / ↓ step a number. Errors appear next to the field and name it.
  7. Every ribbon item gets a 16 px image as well as the 32 px one, and F1 help on every main button, as ClickTo3D already has.
  8. Test each window at 100 %, 150 % and 200 % Windows scaling and on a second monitor in Revit 2024 and 2027 (the oldest and newest .NET).
