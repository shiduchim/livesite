WHAT WE ARE BUILDING
A Revit ribbon button named Export 3D PDF exports a drawing and a spatially bounded, colored GLB model into one PDF. An engineering teammate opens that PDF in Offline 3D PDF Viewer (our separate FastPDF-based application), clicks a location on the 2D drawing, and inspects the corresponding orthographic 3D section. Ordinary PDF readers still display/print the 2D drawing. This is a custom embedded-GLB workflow, not Acrobat-native PRC/U3D. The reader currently seems to work well; focus on the Revit exporter.

TECHNOLOGY
C# Revit API, CustomExporter/IExportContext, temporary Revit 3D views, indexed/shared glTF meshes, streamed binary spooling and an internal GLB writer. Desktop reader: WPF/.NET, PDFium, WebView2, Babylon.js WebGL2 by default and Three.js as the alternative. Rendering settings are distinct from Revit export detail. We are keeping this engine arrangement. No DWF, walk mode or additional engines.

COMPATIBILITY BOUNDARY
The Revit DLL intentionally avoids Core.dll/System.Text.Json inside Revit; an earlier dependency failure required a standalone wire writer with linked pure source files. Keep this isolation.
The DLL writes draft resources, then launches the existing sibling Viewer/Offline3D.FastPDF.Dev.exe with --auto-export <draft-folder> <destination.pdf>. The reader helper calibrates the PDFs and embeds the resources. Preserve that command, layout, filenames, JSON schema, identity references and coordinate conventions; see CURRENT_CONTRACT.md.
The frozen reader accepts plain shared glTF meshes with node matrices. It currently rejects glTF extensions, image textures, external resources and compressed/quantized attributes. Do not introduce meshopt, Draco, KHR_mesh_quantization or EXT_mesh_gpu_instancing into an exporter-only change. Such formats require a separately coordinated reader upgrade.
Do not treat merely raising the 512 MiB scene limit as a performance fix. Preserve bounded parsing, capabilities and integrity checks. Old docs/CONTRACT.md in the original project is stale; CURRENT_CONTRACT.md and the source are the baseline here.
